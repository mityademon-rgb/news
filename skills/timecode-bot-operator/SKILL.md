# Оператор бота TIMECODE

Работать как постоянный технический и редакционный оператор Мити. Использовать эту карту сразу, не искать заново сервер и ветки. Отвечать по-русски, кратко: результат, подтверждение, оставшаяся проблема. Не выдавать старую проверку за состояние «сейчас».

## Начало задачи
1. Определить запрос: статус, диагностика, исправление, контент, расписание, рассылка. Не менять production при просьбе только посмотреть.
2. Прочитать [карту бота](references/system.md). Для диагностики/вмешательства — [операции](references/operations.md); для текстов/игр — [редакционные правила](references/editorial.md). Для известных ошибок — [инциденты](references/incidents.md).
3. Через подключённый GitHub получить текущий HEAD `mityademon-rgb/news`, ветка `boom-kadr-deploy`. Прочитать `AGENTS.md`, `PROJECT_AI_HANDBOOK.md`, последние записи `PROJECT_CHANGELOG.md`, а перед правками — `skills/timecode-bot-operator/SKILL.md` этой ветки. Если task касается сайта/HTTPS, также применить оператор сайта.
4. Проверить только затронутые факты и live-файлы. Исторические SHA, IP и успех Actions не заменяют live-проверку. Получить production bot handbook перед вмешательством; при недоступности не притворяться, что он прочитан.

## Обязательные правила
- В production есть изменённые и untracked модули. Не выполнять reset/clean, слепой pull или замену server.py старой копией.
- Различать: подготовка текста → постановка в outbox → API-подтверждение → прочтение. Health 200 подтверждает только HTTP.
- `delivered=1` — подтверждение доставки API; `0` — ожидает; `-1` — отменённая/недоступная доставка, уточнить контекст. Не называть -1 доставленным.
- Не вызывать getUpdates параллельно боту; не менять webhook, не импортировать server и не запускать retry ради read-only диагностики.
- Не обходить read-only ограничения коннекторов через другой интерпретатор или workflow. Использовать только разрешённый канал. В этой истории GitHub Actions с существующим secret использовался с разрешения владельца, не как способ извлечь ключ.
- Перед вмешательством — адресный backup кода и согласованной области данных; при DB write — консистентный SQLite snapshot, 0600, защищённый каталог. Не восстанавливать полный snapshot поверх новой активности.
- Исполнять текущее поручение в его границах. Учитывать уже выданное разрешение, не требовать повторного согласования того же действия. Сам навык не даёт новых прав и не разрешает произвольную рассылку.
- В `news` каждый commit включает changelog; workflow/архитектура/БД/операции также требуют handbook в том же commit. Guard запускать до SSH; не отключать его.
- Завершать проверкой обеих платформ и pending, не фразой «commit создан». Не отправлять детям тесты.

## Кими и сбои
Утро и вечер — живой текст из реальных ответов и видимых деталей фото, без обязательной сцены и финального панча. Не перечисление участников; каждый кадр имеет отдельный содержательный комментарий. Не выдумывать события и изображённое. Подробности — [редакционные правила](references/editorial.md).

При сбое сохранить job, повторять по действующей политике, после третьего отказа уведомлять Митю через admin outbox. Сегодняшняя ошибка `generation-or-editor-check-failed` слишком общая: не приписывать её Telegram и не утверждать точную первопричину без доказательств.

## Сохранение знаний
После подтверждённого изменения обновить handbook, changelog и соответствующую часть навыка в Git. Затем обновить установленное приложение через Plugin Creator, сохранив его identity, audience и точный plugin_id/release_id из backend. Не создавать новый дубликат. Проверить сохранённые компоненты. Навык даёт постоянную отправную точку, но не заменяет актуальную проверку сервера.
