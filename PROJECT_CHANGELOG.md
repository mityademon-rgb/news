Этот файл — последовательная память проекта. Он отвечает на вопрос: **что изменили, зачем, как проверили и как откатить**.

Актуальное устройство системы описано в [`PROJECT_AI_HANDBOOK.md`](PROJECT_AI_HANDBOOK.md). Журнал не заменяет handbook: после архитектурных, инфраструктурных или эксплуатационных изменений обновляются **оба** файла.

## 2026-10-20 — Регистрация преподавателя и отключаемая ежедневная жизнь

- **Тип:** код / onboarding / доставка сообщений
- **Цель:** отделить учеников от преподавателей и дать взрослым выбор: только уроки по нейросетям или полноценное участие в ежедневных активностях TIMECODE.
- **Изменено:** source `media-center-bot` commit `6949374132d3ce58b2c825139977706e985713a9`: первый вход спрашивает «Ты занимаешься в TIMECODE?». «Да» ведёт к Kids/Media Lab; «Нет, я преподаватель» — к отдельному приветствию и согласию на ежедневные сообщения. Новый `teacher_modes.daily_enabled` по умолчанию выключен; `/daily on`, `/daily off`, callback и кнопка профиля меняют выбор. В режиме «только уроки» UI оставляет «Нейросети» и «Моё», API скрывает повседневные данные и отклоняет игровые POST. Очереди текстов и фото отмечают отложенные сообщения, прямые фоновые отправки проверяют режим; детские статусы начисляются только роли `member`.
- **Связи:** Telegram, MAX, Mini App `/tc/`, `/api/state`, `/api/teacher-mode`, `/api/neuro`, `notification_outbox`, `notification_photo_outbox`, курс `#/ai`.
- **Проверки:** четыре изолированных теста регистрации, прежнего пользователя, переключения, очередей и API; семь тестов Кими, Python/JS syntax, документационный guard, адресный `cmp` старых live daily_status/neuro.js. Workflow проверит оба health и 401 без токена, не отправляя пользователям сообщений.
- **Публикация:** новый workflow `timecode-teacher-mode.yml`; результат проверяется по отдельному run.
- **Откат:** backup `teacher-mode-latest-backup-path`: вернуть `server.py`, `daily_status.py`, `static/neuro.js`, убрать `teacher_mode.py`/README, перезапустить только бота; таблицу `teacher_modes` можно оставить для последующего восстановления выбора.
- **Риски и продолжение:** статус преподавателя сейчас заявительный — ответ «нет» не проверяет личность. Это достаточно для выбора учебной ветки, но не для выдачи административных прав. Личная настройка не может отключить публикации в отдельном групповом чате, если преподаватель состоит в нём.

## Обязательные правила

1. Любое изменение кода, контента, дизайна, assets, конфигурации, workflow или документации получает отдельную запись.
2. Запись создаётся в том же commit, что и изменение. Commit без записи считается незавершённым.
3. Новые записи добавляются сразу под маркером `NEXT ENTRY`, от новых к старым.
4. Указывать только факты. «Опубликовано» допустимо писать лишь после проверки live-состояния.
5. Не записывать пароли, токены, ключи, персональные данные, содержимое сообщений и секретные значения env.
6. Если изменение затрагивает архитектуру, маршруты, source of truth, инфраструктуру, API, БД, сборку, деплой или эксплуатационные риски, одновременно обновить `PROJECT_AI_HANDBOOK.md`.
7. SHA записи определяется историей Git самого файла: `git log -1 --format='%H' -- PROJECT_CHANGELOG.md`. Внутрь записи будущий SHA вписывать не требуется.
