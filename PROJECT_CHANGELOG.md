# TIMECODE — журнал изменений проекта

Этот файл — последовательная память проекта. Он отвечает на вопрос: **что изменили, зачем, как проверили и как откатить**.

Актуальное устройство системы описано в [`PROJECT_AI_HANDBOOK.md`](PROJECT_AI_HANDBOOK.md). Журнал не заменяет handbook: после архитектурных, инфраструктурных или эксплуатационных изменений обновляются **оба** файла.

## Обязательные правила

1. Любое изменение кода, контента, дизайна, assets, конфигурации, workflow или документации получает отдельную запись.
2. Запись создаётся в том же commit, что и изменение. Commit без записи считается незавершённым.
3. Новые записи добавляются сразу под маркером `NEXT ENTRY`, от новых к старым.
4. Указывать только факты. «Опубликовано» допустимо писать лишь после проверки live-состояния.
5. Не записывать пароли, токены, ключи, персональные данные, содержимое сообщений и секретные значения env.
6. Если изменение затрагивает архитектуру, маршруты, source of truth, инфраструктуру, API, БД, сборку, деплой или эксплуатационные риски, одновременно обновить `PROJECT_AI_HANDBOOK.md`.
7. SHA записи определяется историей Git самого файла: `git log -1 --format='%H' -- PROJECT_CHANGELOG.md`. Внутрь записи будущий SHA вписывать не требуется.

## Шаблон записи

```markdown
## YYYY-MM-DD HH:MM MSK — Короткое название

- **Тип:** контент / дизайн / код / инфраструктура / документация / исправление
- **Цель:** зачем понадобилось изменение
- **Изменено:** перечень файлов и фактических изменений
- **Связи:** какие маршруты, компоненты или источники истины затронуты
- **Проверки:** точные команды и ручные проверки
- **Публикация:** не публиковалось / commit создан / workflow успешен / live проверен
- **Откат:** конкретный безопасный способ вернуть прежнее состояние
- **Риски и продолжение:** что осталось непроверенным или что нужно сделать дальше
```
