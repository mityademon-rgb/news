# TIMECODE: обязательный порядок работы

Эти правила действуют для всего репозитория.

## Перед изменениями

1. Полностью прочитать `PROJECT_AI_HANDBOOK.md`.
2. Прочитать последние записи `PROJECT_CHANGELOG.md`.
3. Выполнить `git fetch`, проверить ветку, HEAD и `git status`.
4. Не удалять и не перезаписывать чужие незакоммиченные изменения.
5. Для TIMECODE следовать действующему skill/инструкциям проекта, если они доступны.

## Во время работы

- Делать минимальные адресные изменения.
- Не выполнять production restart, DB write/migration, массовую рассылку, DNS/TLS/nginx/systemd operation без отдельного разрешения владельца.
- Не раскрывать секреты и персональные данные в коде, документации, логах или ответах.
- Не пересобирать `site.js` простой конкатенацией, пока documented bundle drift не устранён.

## Перед завершением

1. Добавить запись в `PROJECT_CHANGELOG.md` в том же commit, что и изменение.
2. Для изменений архитектуры, маршрутов, source of truth, инфраструктуры, API, БД, сборки, deploy или operational risks обновить также `PROJECT_AI_HANDBOOK.md`.
3. Запустить:

   ```bash
   bash scripts/check-project-documentation.sh HEAD WORKTREE
   git diff --check
   ```

4. Зафиксировать в журнале проверки, статус публикации, ограничения и способ отката.
5. Не называть изменение опубликованным до проверки live-состояния.

Для создания заготовки новой записи можно использовать:

```bash
bash scripts/new-change-entry.sh "Короткое название изменения"
```
